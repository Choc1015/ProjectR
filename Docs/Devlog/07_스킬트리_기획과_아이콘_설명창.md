## 이번 목표

- 앞으로 만드는 그래픽이 지금 것과 따로 놀지 않게 규칙을 정한다.
- 예시로 넣어 둔 스킬트리를 실제 기획으로 채운다.
- 스킬 아이콘 64개를 내가 일일이 프롬프트 쓰지 않고 뽑아서 넣는다.
- 노드에 마우스를 올리면 뜨는 설명창을 분위기에 맞게 만든다.

## 진행 과정

### 1. 아트 통일 규칙부터

> 다음을 하기 전에 이제 앞으로 하는 모든 모델, UI 등 그래픽적인 것 지금 만들어진 거와 통일감 있게 만들어야 한다는 것을 규칙을 만들어

`CLAUDE.md`에 규칙을 넣었다. 3D는 로우폴리 + 따뜻한 갈색 톤, 2D는 양피지 + 세피아 잉크 + 금박 + 붉은 밀랍. 제미나이 프롬프트에는 항상 공통 스타일 문구를 붙인다. UI용 공통 문구도 새로 만들었다.

### 2. 세 갈래 이름 정하기

> 스킬트리는 중심에서 3가지로 파생하는 거야. 체력, 마나, 힘. ... 근데 체력, 마나, 힘이라고 이름을 지으면 너무 밋밋하니까 추천을 받을게

자연물(뿌리·샘·칼날), 기사의 덕목(인내·지혜·용맹), 원소, 짐승 문장 등 다섯 세트를 받았고, **B. 인내 · 지혜 · 용맹**으로 정했다.

### 3. 스킬 60개는 맡기고, 모양은 내가 고치기

> B로 가자. 그리고 세부 스킬 목록 일단 알아서 각각 20개씩 짜봐

갈래마다 길 4개 × 스킬 5개로 초안이 나왔다(`Docs/Design/스킬트리_기획.md`). 표에 넣고 보니 노드가 64개라 화면을 넘쳤다.

> 표에 넣어주고 화면 크기 관련은 창을 끌고 확대할 수 있게 만들어

드래그로 이동, 휠로 확대·축소를 넣었다. 그런데 길이 전부 한 줄로 뻗기만 해서 심심했다.

> 좋은데 스킬트리가 너무 단순해. 두 갈래 세 갈래 섞어서 만들어줘

스킬 내용은 그대로 두고 부모만 바꿔서, 세 갈래로 나뉘는 노드와 다른 길에서 갈라져 나오는 길을 섞었다.

### 4. 아이콘 64개: 제미나이를 크롬으로 자동화

64개를 내가 하나씩 프롬프트 쓰고 저장하는 건 너무 반복 작업이었다.

> 내가 일일이 프롬프트 쓰고 넣으면 너무 반복 작업이잖아. 해당 일을 알아서 너가 크롬에서 재미나이한테 작업해서 뽑고 적용시키는 방식을 하고 싶은데

Claude in Chrome 확장을 연결하고 제미나이에 로그인만 해 뒀다. 나머지는 이렇게 돌아갔다.

1. 한 장씩 64번 뽑으면 그림체가 흔들리니까 **4×4 시트로 16개씩, 4장**만 뽑는다.
2. 같은 대화창에서 이어 뽑고, 프롬프트 끝에 UI 공통 스타일 문구를 붙인다.
3. 다운로드한 시트를 스크립트(`Tools/SliceIconSheet.ps1`)로 칸마다 자르고 흰 배경을 지운다.
4. 언리얼에 넣고 스킬 표의 Icon 칸을 채운다.

첫 장만 확인하고 나머지는 그대로 진행시켰다.

> 이대로 진행

![첫 번째 아이콘 시트](./images/07_icon_sheet1.png)

4장 모두 요청한 순서대로 나와서 다시 뽑은 장이 없었다.

### 5. 설명창: 세 번 고쳤다

> 이제 스킬 아이콘에 마우스를 올렸을 때 보이는 설명 이미지를 만들고 적용하자

제미나이로 양피지 카드 틀(모서리 금박 + 위쪽 밀랍 도장)을 뽑아 붙였다. 상태 줄에는 "비용 1 / 먼저 '용맹' 해금 필요"처럼 왜 못 찍는지도 보이게 했다.

**첫 번째 문제: 글씨와 장식이 겹침**

![깨진 설명창](./images/07_tooltip_broken.png)

> 음 글씨가 너무 크거나 여백 때문에 깨진다

글씨를 줄이고, 여백을 모서리 장식 바깥으로 늘렸다.

**두 번째 문제: 도장이 찌그러지고 화질이 깨짐**

![찌그러진 도장](./images/07_tooltip_seal.png)

> 내가 볼 때 이미지가 해상도에 안 맞는 거 같은데 좀 깨져서 보여. 도장 찌그러지잖아

- 9-슬라이스로 늘리면 위쪽 가운데의 도장까지 늘어난다. 그림을 **위·가운데·아래 세 조각**으로 잘라 가운데만 세로로 늘리게 바꿨다.
- 796px 그림을 300px로 그리니 선이 깨졌다. 표시 크기의 1.5배(450px)로 미리 줄여서 넣었다.

![고친 설명창](./images/07_tooltip_fixed.png)

> 좋다

### 6. 손글씨 글꼴

> 이제 상업적으로 사용 가능한 무료 폰트 중에 필기체로 쓴 폰트 찾아서 스킬 설명에 적용시키자

**나눔손글씨 펜**(SIL OFL)으로 정했다. 게임에 넣어 팔아도 무료이고, 펜으로 쓴 느낌이 양피지와 맞는다. 언리얼에는 글꼴 임포트 도구가 없어서 프로젝트 툴셋에 `FontTools`를 추가했다.

**세 번째 문제: 글자 하나가 네모로 깨짐**

![네모로 깨진 글자](./images/07_tooltip_font_tofu.png)

> 보면 무슨 a 같은 걸로 깨져서 보이는데 뭐가 깨진 걸까?

손글씨 글꼴에 가운뎃점 `·`이 없어서 대체 문자(네모)가 나온 거였다. `/`로 바꿨다.

## 문제와 해결

| 문제 | 원인 | 해결 |
|---|---|---|
| 노드 64개가 화면을 넘침 | 원형 배치 반지름이 커짐 | 드래그 이동 + 휠 확대 |
| 트리가 단조로움 | 길이 전부 일직선 | 부모를 바꿔 2·3갈래를 섞음 |
| 아이콘 64개 반복 작업 | 프롬프트·저장·자르기를 손으로 | 크롬 자동화 + 4×4 시트 + 자르기 스크립트 |
| 설명창 글씨와 장식 겹침 | 여백이 장식보다 작음 | 글씨 축소, 여백·최소 높이 확보 |
| 도장 찌그러짐 | 9-슬라이스가 위쪽 가운데를 늘림 | 위·가운데·아래 세 조각으로 그림 |
| 테두리 화질 깨짐 | 큰 그림을 크게 줄여 그림 | 표시 크기의 1.5배로 미리 축소 |
| 글자가 네모로 깨짐 | 손글씨 글꼴에 `·` 없음 | 다른 기호로 교체 |

배운 것
- 반복 작업은 **"내가 하면 반복인 일"이라고 말하고 통째로 맡기는 게** 제일 빨랐다. 나는 로그인과 첫 장 확인만 했다.
- UI 그림은 화면에서 직접 보고 스크린샷으로 짚어 주니 원인이 바로 나왔다. 말로 설명하는 것보다 확실했다.
